Samlab API

Integrasjonsdokumentasjon for Samlab - community-portalen for coworking-hus og kontorfellesskap. REST-endepunkter under samlab/v1, PHP-hendelser for server-side integrasjon, og en tester så du kan prøve kallene rett fra denne siden.

Introduksjon

Samlab-API-et har to flater:

  • REST-endepunkter under navnerommet samlab/v1 - for klienter og eksterne systemer.
  • PHP-hendelser (actions og filters) - for server-side integrasjon i samme WordPress, f.eks. en bro som videresender hendelser til CRM, Slack eller husets driftssystem.

Prinsipper

Samtykke før kontakt. Ingen kobles uten at begge parter har takket ja - motpartens kontaktinfo finnes ikke i noe svar før koblingen er godkjent.

Aggregert, aldri salgsdetaljer. Utfall er kategori og notat - det finnes ikke noe beløpsfelt, og rapporter navngir aldri hvem som gjorde hva.

Brukerens rettigheter gjelder alltid. Hvert kall håndheves med capabilities og partskap - en integrasjon ser aldri mer enn brukeren den opptrer som.

Kom i gang

1. Opprett en integrasjonsbruker med applikasjonspassord

Opprett en egen WordPress-bruker for integrasjonen med rollen Medlem (eller Moderator hvis integrasjonen skal opptre som verten). Generer et applikasjonspassord på brukerens profilside i wp-admin - det gir Basic auth over HTTPS uten å dele hovedpassordet, og kan trekkes tilbake når som helst.

2. Test API-et

Fyll inn base-URL og legitimasjon i testeren under, og prøv GET /koblinger - eller fra terminalen:

curl -u 'integrasjon:xxxx xxxx xxxx xxxx xxxx xxxx' \
  https://huset-ditt.no/wp-json/samlab/v1/koblinger

Autentisering

Alle endepunkter krever en innlogget WordPress-bruker med portaltilgang (capability samlab_read_portal - rollene Medlem, Bedriftsredaktør og Moderator har den, samt administrator og redaktør).

Fra portalens frontend

Portalskallet eksponerer window.samlabRest med base-URL og et ferskt wp_rest-nonce. Send nonce-et i X-WP-Nonce-headeren sammen med sesjonscookien (credentials: 'same-origin').

Server-til-server

Basic auth med applikasjonspassord over HTTPS:

Authorization: Basic base64( 'brukernavn:applikasjonspassord' )

Merk

Integrasjonen arver brukerens rettigheter - verken mer eller mindre. Partskapsvaktene betyr at en integrasjonsbruker bare ser koblinger den selv er part i. Trenger du et bredere bilde (alle hendelser til et CRM), er PHP-hendelsene riktig verktøy - ikke moderatorrolle på integrasjonsbrukeren.

Rate limiting

Assistent-endepunktet er begrenset til 15 kall per 5 minutter per bruker og svarer 429 over grensen - svaret har ingen retry-headere: vent noen minutter. Øvrige endepunkter er bygget for husets hverdag - kall dem i menneskelig takt, ikke til masseuttrekk. Volumvern utover dette hører hjemme på server-nivå og bør være på plass i normal WordPress-drift.

Koblingsmodellen

Koblinger er Samlabs kjerne: fasiliterte introduksjoner mellom to parter (en bedrift eller en person). API-et håndhever statuskjeden strengt:

foreslått→ forespurt→ godkjent→ introdusert→ fulgt opp (avvist er terminal sidegren)
  • foreslått - forslaget ligger i vertens kø. Vises aldri for partene.
  • forespurt - verten har spurt begge parter; hver part svarer ja eller nei.
  • godkjent - begge har takket ja. Først nå deles kontaktinfo, og statusen kan ikke nås på annen måte.
  • introdusert / fulgt opp - verten har introdusert partene; utfallet («ble det noe?») kan registreres.
  • avvist - verten trakk forslaget, eller en part takket nei. Hvem som takket nei, deles aldri.

API-endepunkter & test

Base-URL

REST-navnerommet ligger fast, uavhengig av portal-stien:

https://huset-ditt.no/wp-json/samlab/v1/

Test API-et direkte fra siden

Legitimasjonen brukes kun i denne fanen, rett mot din WordPress - den sendes aldri til andre. Skriv aldri inn applikasjonspassord på dokumentasjonssider som ikke serveres fra husets eget domene over HTTPS.

Ikke konfigurert - testerne genererer likevel curl-kommandoer du kan kjøre fra terminalen.

CORS

Kall rett fra nettleseren fungerer når denne siden ligger på samme domene som WordPress (f.eks. /api-dokumentasjon.html på husets nettsted). Fra andre domener blokkerer nettleseren normalt kallet - bruk da curl-kommandoen testeren genererer.

Koblinger

GET/koblinger

Krever samlab_read_portal. Returnerer kun koblinger brukeren selv er part i - direkte, eller som kontaktperson for en bedrift. Nyeste først, maks 100.

Svar

{ "koblinger": [ {
  "id": 42,
  "tittel": "Brygga Design ↔ Jonas Dal",
  "begrunnelse": "Jonas trenger designhjelp til lanseringen.",
  "status": "forespurt",
  "status_etikett": "Forespurt",
  "min_part": "b",
  "mitt_samtykke": "venter",      // venter | ja | nei
  "motpart": "Brygga Design",
  "motpart_kontakt": null,          // { navn, epost } først fra godkjent
  "utfall": null,                   // { slug, etikett, notat } når registrert
  "opprettet": "2026-08-30"
} ] }
POST/koblinger/<id>/svar

Krever samlab_read_portal + at brukeren er part i koblingen. Koblingen må stå i forespurt.

Parametre

NavnTypeBeskrivelse
svarstringpåkrevdja eller nei

Begge ja løfter koblingen til godkjent og varsler begge parter; ett nei setter avvist og gir motparten et nøytralt varsel uten navn. Svaret er koblingsobjektet som i GET /koblinger.

  • 403 ikke part
  • 404 ukjent kobling
  • 409 venter ikke på svar
POST/koblinger/<id>/utfall

Krever samlab_read_portal + partskap. Koblingen må være introdusert eller fulgt_opp; en introdusert kobling løftes til fulgt opp når utfallet føres.

Parametre

NavnTypeBeskrivelse
utfallstringpåkrevdmote, avtale, henvisning eller ingenting
notatstringvalgfriMaks 500 tegn. Kun kategori og notat - det finnes ikke noe beløpsfelt.
  • 403 ikke part
  • 404 ukjent kobling
  • 409 utfall før introduksjonen

Varsler og brukere

GET/varsler

Krever samlab_read_portal. Innlogget brukers varsler (maks 20, nyeste først) med uleste-teller - alltid brukerens egne, aldri styrbart med parametre.

Svar

Krever samlab_read_portal. Markerer alle brukerens varsler som lest. Svar: { uleste: 0 }

Assistenten

POST/assistent

Krever samlab_read_portal. Finnes kun når assistent-modulen er på - ellers 404. Kallet går server-side mot Claude API; nøkkelen forlater aldri serveren.

Parametre

NavnTypeBeskrivelse
meldingstringpåkrevdSpørsmålet, maks 4000 tegn
historikkarrayvalgfri[{ rolle: user|assistant, tekst }] - avgrenses server-side til de siste 10

Svar

{ svar, navn }. Samtaler logges aldri; ubesvarte spørsmål lagres anonymt (kun spørsmålstekst) i vertens kø når innstillingen er på.

  • 503 nøkkel ikke satt
  • 429 over rate-grensen
  • 400 tom melding
  • 502 feil mot Claude API

Webhooks (PHP-hendelser)

Samlab sender ikke webhooks selv - i stedet eksponerer pluginen alle hendelser som WordPress-actions, så du bygger akkurat den webhooken du trenger med en liten bro-plugin i samme WordPress. Da ser du alt, uansett hvilken bruker som utløste det:

<?php // wp-content/mu-plugins/samlab-bro.php
// Videresender koblingshendelser til ditt system.
add_action( 'samlab_kobling_status_endret', function ( $kobling_id, $status, $gammel, $user_id ) {
    wp_remote_post( 'https://ditt-system.no/webhook/samlab', array(
        'timeout' => 5,
        'headers' => array( 'Content-Type' => 'application/json' ),
        'body'    => wp_json_encode( array(
            'hendelse' => 'kobling_status_endret',
            'kobling'  => $kobling_id,
            'status'   => $status,
            'forrige'  => $gammel,
        ) ),
    ) );
}, 10, 4 );

Retry og signering er ditt ansvar

Broen over er fyr-og-glem. Trenger mottakeren garantert levering, legg kallene i en kø (f.eks. Action Scheduler) og signer payloaden med en delt hemmelighet (HMAC) så mottakeren kan verifisere avsenderen.

Feilkoder

Feilrespons-format

Feilsvar følger WordPress-formatet - meldingene er norske og generiske, og lekker aldri konfigurasjonsdetaljer:

{
  "code": "samlab_feil_status",
  "message": "Koblingen venter ikke på svar.",
  "data": { "status": 409 }
}
HTTPBetyr
400Ugyldige parametre (enum-brudd, tom melding)
401Ikke innlogget, eller ugyldig nonce/legitimasjon
403Mangler capability eller partskap
404Objektet finnes ikke - eller assistent-modulen er av
409Handlingen passer ikke objektets tilstand (svar utenfor forespurt, utfall før introduksjon)
429Over assistentens rate-grense
502 / 503Assistenten: feil mot Claude API / API-nøkkel ikke satt

Kodeeksempler

JavaScript (fetch, fra portalen)

fetch( window.samlabRest.url + 'samlab/v1/koblinger/42/svar', {
  method: 'POST',
  credentials: 'same-origin',
  headers: {
    'Content-Type': 'application/json',
    'X-WP-Nonce': window.samlabRest.nonce
  },
  body: JSON.stringify( { svar: 'ja' } )
} ).then( r => r.json() ).then( console.log );

Python (requests)

import requests

svar = requests.post(
    "https://huset-ditt.no/wp-json/samlab/v1/koblinger/42/utfall",
    auth=("integrasjon", "xxxx xxxx xxxx xxxx xxxx xxxx"),
    json={"utfall": "avtale", "notat": "Rammeavtale om design"},
    timeout=10,
)
svar.raise_for_status()
print(svar.json())

PHP (WordPress HTTP-API)

$svar = wp_remote_get( 'https://huset-ditt.no/wp-json/samlab/v1/koblinger', array(
    'headers' => array(
        'Authorization' => 'Basic ' . base64_encode( 'integrasjon:xxxx xxxx xxxx xxxx xxxx xxxx' ),
    ),
) );
$koblinger = json_decode( wp_remote_retrieve_body( $svar ), true );

Spilleregler for integrasjoner

  • Stabilitet: alt med samlab_-prefiks er dokumentert API og endres aldri uten versjonsbump. Nye felter kan komme til i svar - vær tolerant for ukjente nøkler.
  • Personvern: respekter det API-et selv håndhever. Ikke lagre motpartsdata lenger enn du trenger, og ikke forsøk å rekonstruere hvem som takket nei eller hvem som spurte assistenten om hva - API-et gir det ikke, med vilje.
  • Skriv aldri utenom flyten: koblingsstatuser endres kun via svar- og utfallsendepunktene eller vertens kontrollpanel. En integrasjon som redigerer post-meta direkte, bryter samtykkegarantien.
  • Portalinnhold er internt: alt bak innloggingsporten er noindex og utenfor offentlige søk. Det samme ansvaret følger dataene inn i din integrasjon.
